# Among8 — соло и дуэль интуиции

10 проверенных вопросов о мире, выбор 0–100% через 100 квадратов, **15 секунд** на отправку ответа. Русский интерфейс, Manrope, четыре процедурных 3D-персонажа и синтезированные звуки с выключателем.

## Режимы

- **Играть одному:** имя, персонаж, 10 вопросов, личный итог. Ответ сразу раскрывает реальность; отсутствие отправленного ответа за 15 секунд даёт 0 баллов.
- **С другом:** первый игрок создаёт комнату и отправляет ссылку или восьмизначный код. Второй входит со своим именем и персонажем. Создатель запускает общий трёхсекундный отсчёт. Игроки отвечают одновременно; чужой процент и правильный ответ скрыты до двух отправленных ответов или истечения таймера. После раскрытия видны оба имени, два процента и реальность. Следующий раунд и реванш начинаются после согласия обоих.

## Размещение

- Исходники: https://github.com/alinachandel-max/Among8
- GitHub Pages: папка `docs/`, ветка `main`.
- Сервер и основная версия: https://among8-duel.alinachandel.chatgpt.site
- В `public/config.js` указан адрес API для версии GitHub Pages; на основном домене используется тот же origin.
- Эти адреса являются настройками проекта; статус публикации подтверждается отдельно при deployment.

GitHub Pages обслуживает статические файлы. Сервер запускается как Cloudflare Worker через Sites, а комнаты, результаты и дедлайны хранятся в **D1 (SQLite)**. `localStorage` содержит только секрет возвращения в комнату и предпочтение звука, не является базой результатов.

## Правила подсчёта

Абсолютная ошибка в процентных пунктах: 0–2 → 100; 3–5 → 80; 6–10 → 60; 11–15 → 40; 16–20 → 20; более 20 → 0. Максимум 1000. Скорость в пределах 15 секунд не даёт бонуса. Невыбранный или неотправленный ответ считается пропуском и даёт 0; выбранные 0% являются настоящим ответом.

Средняя ошибка на финале рассчитывается только по отправленным ответам. Пропуски показаны отдельно; при отсутствии ответов средняя ошибка — прочерк. Ничья определяется равенством суммы баллов.

## Синхронизация и безопасность

- Серверный дедлайн — источник истины. Изменение часов телефона и перезагрузка страницы не добавляют времени.
- Клиенты обновляют состояние примерно раз в 850 мс, в фоновой вкладке — реже. Небольшая задержка раскрытия зависит от соединения; обоим выдаётся один итог раунда.
- Игрок получает только свой процент до раскрытия. Тексты фактов, ответ, объяснение и источник приходят после раскрытия; исходники вопросов открыты в GitHub, поэтому это дружеская игра, не защищённый от изучения исходников турнир.
- Анонимный токен игрока: 256 случайных битов. В базе сохраняется SHA-256, сырой токен не возвращается сервером и не включается в приглашение. Знания кода комнаты недостаточно для чтения закрытой игры или изменения чужого ответа.
- На сервере проверяются роль, фаза, номер раунда, диапазон процента и срок ответа. Повторная отправка того же ответа безопасна; изменить ответ нельзя. Условные обновления SQLite предотвращают повторный подсчёт баллов и занятие одного места двумя гостями.
- Комнаты недоступны через 24 часа; удаление истёкших записей выполняется при создании следующих комнат. Это не гарантированное физическое удаление ровно через 24 часа.
- Ограничены частота создания/входа и размер запросов. Для лимитов используются краткоживущие хэши IP с временным интервалом, исходный IP не сохраняется в игровых таблицах. Имена и игровые ответы видны участникам комнаты.
- Аккаунтов, паролей, оплаты, рекламной аналитики и статистики вымышленных игроков нет.
- При потере связи таймер не останавливается. Можно перезагрузить страницу на том же устройстве и вернуться в ту же комнату. Если один игрок явно вышел, комната закрывается.

## Локальный запуск

Нужен Node.js 24+ (используется встроенный `node:sqlite`):

```sh
node scripts/dev.mjs
```

Открыть http://127.0.0.1:8082. База создаётся в `development.sqlite`, миграции применяются автоматически только локальным dev-сервером. В production схемой управляют миграции Sites.

## Сборка и изменения схемы

```sh
node scripts/build.mjs
```

Создаются Worker `dist/server/index.js`, статические файлы, метаданные Sites, SQL-миграции и папка `docs/` для GitHub Pages. Сборка не скачивает зависимости. После правок исходников пересобирать `docs/`, не править её вручную.

`db/schema.ts` — схема Drizzle, `drizzle/` — сгенерированные SQL и история. Для изменения схемы нужны зафиксированные dev-зависимости из `pnpm-lock.yaml`:

```sh
pnpm install --frozen-lockfile --ignore-scripts
node node_modules/drizzle-kit/bin.cjs generate
```

Пакеты Drizzle проверены по официальным метаданным npm: проекты drizzle-team, MIT / Apache-2.0, версии 0.31.10 / 0.45.2 совпадают с комплектным шаблоном Sites. Установочные скрипты отключены. Они используются для генерации миграций и не входят в браузерную игру или Worker.

## Проверки

```sh
node --test tests/server.test.mjs
PLAYWRIGHT_MODULE=/path/to/playwright node tests/browser.cjs
```

Серверные проверки: полный цикл двух режимов, точность счёта, дедлайн, пропуски, нулевой ответ, защита скрытых ответов и токенов, конкурирующие входы/отправки/готовность, реванш, срок комнат, CORS и валидация. Браузерные проверки запускают две независимые сессии, проходят 10 раундов дуэли и 10 соло, проверяют восстановление, пропуск, реванш, переключатель звука и 360/390/430/768/1440 px.

## Файлы

- `public/` — HTML, CSS, клиент, WebGL-персонажи, Web Audio, локальный шрифт.
- `server/game.mjs` — API и правила игры, совместимые с Workers.
- `server/questions.json`, `SOURCES.md` — проверенные факты и методология.
- `db/`, `drizzle/` — описание базы и миграции.
- `scripts/` — локальный запуск, SQLite-адаптер, сборка.
- `.openai/hosting.json` — идентификатор Sites и логическая привязка D1. Секретов не содержит.
- `docs/` — сгенерированная версия GitHub Pages.

Шрифт Manrope распространяется с SIL OFL 1.1 (`public/fonts/OFL.txt`). Персонажи построены из собственной геометрии; звуки синтезируются локально. В браузерах без WebGL есть текстовый запасной персонаж. Звук включается только после действия пользователя, с учётом ограничений мобильных браузеров; для reduced motion персонажи статичны. На физических телефонах отдельный прогон ещё нужен.
